# 指标与埋点

## 指标字典

| 字段 | 说明 |
|---|---|
| 名称与 ID | 与团队术语一致 |
| 决策与用户价值 | 指标改变时会做什么 |
| 定义 | 分子、分母、事件、去重实体、排除项 |
| 窗口 | 事件时间/处理时间、时区、滚动或自然周期 |
| 数据 | 来源表/字段、粒度、更新延迟、负责人（已知时） |
| 分析 | 维度、cohort、基线、可比性限制 |
| 目标与告警 | 方向、阈值及依据、最小有效数据条件、处置动作 |

根据业务建立用户价值结果、输入因素、体验/风险护栏、收入与成本。北极星适合形成共同方向时采用；不能用一个数字掩盖相互冲突的用户结果。

AI 产品可区分任务完成、用户采纳/修改、失败/人工接管、成本、延迟和质量评测。生成次数不是天然的价值指标；工具返回成功也不一定意味着用户问题已解决。

看板按决策频率和负责对象组织，只展示会影响行动的指标。线图适合时间变化，漏斗需同一主体和顺序窗口，留存用固定 cohort；没有数据时交付结构规格，不绘制貌似真实的趋势。

## 事件契约

先列分析问题，再反推必要事件，避免所有按钮都记录。

| 事件 | 精确触发条件 | 产生端 | 主体/去重 | 属性与类型 | 版本 | 验证 |
|---|---|---|---|---|---|---|
| 实际事件名 | 点击、服务成功、处理结束等 | 客户端/服务端 | 用户/账号/任务 + event_id | 必填、可空、枚举、单位 | schema 版本 | 如何复现与对账 |

区分点击提交、请求接收、业务成功；说明失败、重试、重复事件、离线补发和跨端身份。客户端点击不能充当真实成交，权限拒绝不能被记录为成功。

属性只保留分析所需内容，个人信息的哈希不自动等于匿名。若采集模型输入、输出、检索内容或工具参数，应分别说明发送前与存储前的裁剪/脱敏、访问权限、保留期限、删除机制及采样方式。失败样本过采样时不能直接当总体失败率。

埋点验收覆盖：正确时机、字段类型、重复/漏报、时区、身份合并、失败分支、源系统对账、版本兼容。只有写出规格并不表示数据已开始采集。
