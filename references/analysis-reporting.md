# 数据分析、实验与周报

## 变化诊断

先检查数据新鲜度、口径变更、缺失、去重、采样和事件覆盖，再解释业务变化。选择相同长度、时区和可比季节的时间窗；不同周期或促销影响单列说明。

展示绝对量、分母和变化，再按合理维度拆解。漏斗检查同一实体与转化窗口，留存检查 cohort 定义和观察完整性。分群变化可能来自流量构成，不把总体变化直接归因于功能。采用整体与分组结果一起核对，避免只挑显著群体。

结论使用“观察到”“与……一致”“可能由……解释”；只有设计与证据支持时才使用因果措辞。每个关键解释带验证方式。

## A/B 分析检查

1. 读取原假设、随机化单位、分流比例、主要指标、护栏、分析窗口、最小可检测效果和停止规则；未知项明确列出。
2. 检查实验分配和指标采集是否可信，包括样本比例异常（SRM）、污染、重复用户、跨组干扰、曝光与分析人群口径。SRM 应基于适当的分配/曝光日志与设计比例，不能只检查转化者构成。
3. 报告样本量、基线、处理值、绝对变化、相对变化、效果区间和使用的方法。分母和假设不足时只做描述统计，不能虚构 p 值或置信区间。
4. 处理多次查看、提前停止、多重比较和事后分群；探索性结果单列，不能挑最好的 p 值作为主要结论。贝叶斯或序贯方法需说明模型与适用停止规则，不和固定样本方法混用。
5. 同时检查业务意义、护栏及成本。统计不显著不等于无效；没有足够证据证明等效，也不能称“两者一样”。数据质量检查失败时，先诊断而非发布胜出结论。

输出建议可以是上线、扩大验证、继续观察、修订或停止，并说明证据限制。文档建议不等于执行发布。

方法校核来源：Microsoft Research 的 [SRM 诊断说明](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/)。这是方法参考，不属于本包“近两年 GitHub Skill”计数。

## 周报与复盘

根据受众选结构：管理层关注结果、业务影响和决策；项目团队关注交付、阻塞和依赖；销售/营销关注同口径漏斗、渠道、成本与后续动作。无须同时输出五份报告。

```text
周期、受众与资料范围
本周结果：已完成事项及证据，区分计划/进行中/已发布
指标变化：本期、可比上期、目标、分母和口径；缺失明确标注
解释与风险：事实、原因假设、影响及需核查项
需要的决策：具体选择与依据
下期行动：动作、已确认负责人/时间、验收方式
```

没有上期数据时不算环比；没有真实原话时不编用户反馈；负责人和时间未知时不替团队承诺。没有量化数据也能依据工作记录写状态周报，但要区分活动与业务成果。

示例：本期转化 12/100，上期 10/100，转化率增加 2 个百分点、相对增加 20%。仅凭这两个数字不能认定统计显著，更不能宣称改版导致提升。
